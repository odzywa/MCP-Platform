Jedna odpowiedź na pytanie:
Jak AI (Claude, ChatGPT, Copilot) może wywoływać Twoje narzędzia,
API i komendy — bez dostępu do całego systemu?
MCP Platform tworzy izolowane kontenery z dokładnie tymi narzędziami które chcesz udostępnić. AI pyta kontener, kontener wykonuje operację, AI dostaje odpowiedź. Nic więcej nie jest dostępne.

🔄 Jak to działa — cały przepływ w 5 krokach

Krok 1
📦 Definiujesz narzędzia
Opisujesz CO AI ma robić — np. "wykonaj komendę oc get" albo "wywołaj to API". Robisz to w Szybkim starcie, Kreatorze zaawansowanym lub Package Generator.
↓
Krok 2
🖥️ Platforma generuje konfigurację
Control plane tworzy pliki: tools.json, policy.json, runtime-config.json. Opisują co wolno uruchamiać i jak.
↓
Krok 3
🐳 Operator uruchamia kontener Docker
Kontener jest rootless (user 1000:1000), read-only filesystem, z limitem 512MB RAM i 1 CPU, odciętymi uprawnieniami (cap_drop: ALL) i izolacją sieciową.
↓
Krok 4
🔌 Serwer MCP nasłuchuje
Kontener wystawia endpoint np. http://mcp.dom:19500/mcp — wklejasz go do Continue, OpenWebUI lub innego klienta AI.
↓
Krok 5
🤖 AI korzysta z narzędzi
Gdy AI chce np. pobrać dane z API, wysyła zapytanie do endpointu MCP. Kontener wykonuje operację i zwraca wynik. AI widzi tylko wynik — nic więcej.

📄 OpenAPI Auto-MCP — MCP z dokumentacji REST API

Jak to działa?
Zamiast ręcznie definiować tools, podajesz URL serwisu który ma dokumentację OpenAPI (openapi.json). Platforma uruchamia kontener z silnikiem FastMCP.from_openapi() który:
1. Pobiera spec z BACKEND_BASE_URL/openapi.json lub OPENAPI_SPEC_URL
2. Automatycznie tworzy osobny tool MCP dla każdego endpointu REST
3. Kieruje wywołania narzędzi bezpośrednio do serwisu backendowego
Żadna ręczna konfiguracja tools nie jest wymagana — nazwy, opisy i parametry pochodzi z dokumentacji spec.

Kiedy używać?

✅ Serwis ma gotową dokumentację openapi.json / swagger.json
✅ Chcesz udostępnić wiele endpointów bez pisania każdego ręcznie
✅ API zmienia się często — spec auto-odświeża tools przy restarcie
✅ Zewnętrzne serwisy z publicznym spec (GitLab, Jira, własne API)

❌ Serwis nie ma dokumentacji OpenAPI → użyj HTTP Gateway lub Shell

Jak uruchomić?

1. Idź do Kreator zaawansowany
2. Krok 1 — wybierz silnik 📄 OpenAPI Spec
3. Wpisz URL serwisu (np. http://moja-api:8000)
4. Opcjonalnie: URL do spec, token autoryzacji
5. Krok 2 → 3 → 4 — reszta jak zwykle

Kontener startuje z obrazem mcp-runtime-openapi:latest.

💡 Jak działa Allowed Prefix?
Wpisujesz prefix np. oc get
→ AI może wywołać oc get pods -n prod ✅
→ AI nie może wywołać oc delete pod xyz ❌
→ AI nie może wywołać oc exec ❌

Działa nawet gdy komenda ma ${'{'}*args{'}'} — platforma sprawdza prefix po podstawieniu argumentów.
⚠️ Bezpieczeństwo kontenera jest zawsze włączone
Niezależnie od tego co skonfigurujesz w polityce, każdy kontener uruchamia się z:
🔒 read_only=True — filesystem tylko do odczytu
🔒 cap_drop=ALL — zero uprawnień systemowych
🔒 user=1000:1000 — nie jako root
🔒 mem_limit=512MB — limit pamięci
🔒 no-new-privileges — nie może eskalować uprawnień

💡 Przykłady zastosowań

🌐
REST API firmy
Masz wewnętrzne API (api.firma.pl). Tworzysz serwer MCP → AI może pytać "znajdź umowy z 2024" → kontener wywołuje API → AI dostaje wyniki. Token jest tylko w kontenerze, AI go nie widzi.
🔴
OpenShift / Kubernetes
Tool: oc get ${'{'}*args{'}'} z prefixem oc get → AI może zapytać "jakie pody działają w prod?" → wykonuje oc get pods -n production. Nie może oc delete — zablokowane policy.
🗄️
Baza danych (psql)
Budujesz własny obraz z postgresql-client (Runtime Image Builder) → tool: psql -h db.firma.pl -U user -c "${'{'}query{'}'}" → AI może czytać dane z DB bez dostępu do hosta.
📄
OpenAPI Auto-MCP (GitLab / Jira / własne API)
Masz serwis z openapi.json (np. GitLab CE, Jira, własne FastAPI). Kreator zaawansowany → silnik OpenAPI Spec → wpisz URL → platforma automatycznie tworzy tool dla każdego endpointu. AI może od razu pytać o zasoby — zero ręcznej konfiguracji tools.

⌨️ Jak pisać komendy shell — zmienne

${'{'}zmienna{'}'} — jeden parametr

Każde ${'{'}var{'}'} = jeden argument. AI podaje konkretną wartość.

Przykład:
Tool: oc get pods -n ${'{'}namespace{'}'}
AI wywołuje: namespace = "production"
Wynik: oc get pods -n production

${'{'}*args{'}'} — pełny dostęp (multi-arg)

${'{'}*args{'}'} = AI podaje wszystkie argumenty naraz. Runtime rozdziela je przez shlex.split.

Przykład:
Tool: oc get ${'{'}*args{'}'}
AI wywołuje: args = "pods -n production -o json"
Wynik: oc get pods -n production -o json
🛡️ Bezpieczeństwo: Runtime używa subprocess.run() bez shell=True — żadna iniekcja przez znaki specjalne nie przejdzie. Dodatkowo policy sprawdza prefix komendy przed wykonaniem.

❓ Najczęstsze pytania

Wpisałem postgres-client w Image Builder i dostałem błąd 100.
Błąd 100 z apt-get = paczka nie istnieje. Na Debianie prawidłowa nazwa to postgresql-client (nie postgres-client). Zawsze sprawdzaj nazwy na packages.debian.org.
Mam repo GitHub z gotowym serwerem MCP w C# / Node.js — czy mogę go zaimportować?
Nie bezpośrednio. Import JSON w Szybkim starcie działa tylko z Package JSON tej platformy (format z polami tools, runtime_class, policy). Dla zewnętrznych serwerów MCP: uruchom go osobno i zarejestruj endpoint w Zewnętrzne MCP. Jeśli repo ma Dockerfile, użyj Runtime Image Builder.
Jak dać AI dostęp do pełnego oc get bez definiowania 20 komend?
Użyj składni oc get ${'{'}*args{'}'} — AI podaje wszystkie argumenty naraz (np. "pods -n production -o json"). W kroku bezpieczeństwa ustaw Dozwolony prefix: oc get — AI może TYLKO wykonywać oc get ..., nie oc delete ani inne komendy.
Czy AI może zrobić cokolwiek chce na moim serwerze?
Nie. Trzy warstwy ochrony: (1) Policy — sprawdza prefix komendy i dozwolone binarki; (2) subprocess bez shell=True — żadna iniekcja; (3) Hardening kontenera — rootless, read-only FS, cap_drop ALL, izolacja sieciowa.
Jak zmienić tools bez restartu serwera?
Edytuj tool na stronie serwera → kliknij ♻️ Reload Config. Kontener przeładuje tools.json i policy.json bez restartu — zmiana zajmuje sekundy.
Jak podłączyć serwer MCP do Continue lub OpenWebUI?
Na stronie uruchomionego serwera (Moje serwery → kliknij serwer) znajdziesz sekcję 🔌 Jak podłączyć do klienta AI? z gotowymi snippetami dla Continue, OpenWebUI i innych klientów. Każdy snippet jest klikalny — kopiuje się do schowka.
Jak zarejestrować nowe konto?
Idź na /register, wpisz login, hasło i żądaną rolę. Konto jest nieaktywne do momentu akceptacji przez administratora. Admin akceptuje w 👥 Użytkownicy i nadaje rolę.
