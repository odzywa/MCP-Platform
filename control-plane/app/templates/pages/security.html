📖 Jak działa policy? Co blokuje, a co nie?
🔒 require_read_only
Wymusza żeby każdy tool miał mode: read-only. Jeśli tool ma read-write, runtime odrzuca wywołanie z błędem policy.
🚫 block_write_tools / block_destructive_tools
Dodatkowe flagi sprawdzane przez runtime przed wykonaniem narzędzia. Można blokować klasy operacji bez edytowania każdego toola osobno.
⌨️ allowed_binaries
Tylko dla shell tools. Lista dozwolonych binarek — np. ["curl", "jq"]. Runtime odrzuca wywołania używające innych komend. Pusta lista = brak ograniczeń.
⚠️ Co policy NIE kontroluje
Policy działa na poziomie aplikacji. Hardening kontenerów (rootless, cap_drop, read-only FS) to osobna warstwa i jest zawsze aktywna niezależnie od ustawień policy.
